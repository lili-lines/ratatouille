**What I learned** <br>
The gyro has a bias, −2°/s at rest: measured at startup and subtracted, only 0.007°/s remain. The encoders give 1151 counts per wheel turn, so 0.087 mm per tick, and they only see the wheel, not the floor. The position they compute is the middle of the axle, not the nose.

In this post we look at how the mouse knows its position in the maze.
Two kinds of sensors give two things: the wheel encoders the position $(x, y)$, the Inertial Measurement Unit (IMU) the orientation, the heading. <br>
We also test the reading and the calibration of each one on the breadboard.

⏰ Plan B, in case we have no wheel encoder: we can use an optical flow sensor PMW3901 that measures displacement. Its advantage is being more precise, but it must be mounted on a mast at ≥80 mm above the ground.


## 1. The IMU and wheel encoder sensors

We have 3 sensors to know the position and navigate in the maze. 2 wheel encoders measuring the distance travelled by their wheel. These sensors give us the position $(x, y)$, the one of the point halfway between the 2 wheels, at the axle. And the IMU gyro, which gives us the heading, which way the robot faces. <br>
Each one covers the other's weakness, encoders drift when a wheel slips, so spin without moving, and the gyro drifts slowly over time.

We can see the gyro bias: the sensor returns -2°/s between each value while the gyro is not moving.
To correct this, we calibrate the gyro value at startup, then in the loop we subtract the bias before integrating:

```cpp
float gyroZ_dps = (gyroZraw / 131.0) - gyroZ_bias;
```

After this correction there is still a drift, but a small one: even calibrated, the gyro drifts slowly. To correct this in the v2 we can use the wheel encoder.
</div>
</div><br>

<div class="two-col">
<div class="col" markdown="1">
init value ~ 0 & turn of 90° clockwise <br>
value = -88.87 <br>
error = |headingDeg_measured − real_angle| <br>
error = |90 − 88.87| = 1.13° < 5° so ✅ <br>
</div>
<div class="col" markdown="1">
Now let's compute the CPR, for this we turn the wheel by hand, exactly 10 full turns. <br>
init value -166 <br>
value after 10 turns -11677 <br>
CPR = (final value − init value) / 10 <br>
CPR ≈ 1151
</div>
</div>

So we can now compute the mm per count:
the number of mm the mouse travels in one wheel turn, circumference ≈ 100mm (Ø32mm) <br>
mm per count = 100mm / 1151 ≈ 0.087mm per pulse

```cpp
const float MM_PER_TICK = 100.0 / 1151.0;               // ≈ 0.087 mm
const long TICKS_TARGET = (long)(300.0 / MM_PER_TICK);  // 30cm → 3452 ticks
```

This converts a distance in mm into a number of pulses, which is the unit of the wheel counter. So the mouse will count up to 3452 to travel 30cm.

For the encoder, the mouse is on a stand and the wheels turn free, so this is the rotation converted into mm and not a real travel. The slope is the forward speed of the wheel, median over 1 s windows: <br>
